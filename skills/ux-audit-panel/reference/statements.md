## 1. Consistency

*Explanation: Users should not have to wonder whether different words, situations, or actions mean the same thing. Follow platform and industry conventions.*

- **row 4** — The content and visual design of UI is focused on the essentials
- **row 5** — Content and features to support primary goals is prioritized
- **row 6** — Headers and short blocks of info or text are used.
- **row 7** — The information is easy to scan. The app/website uses a visual hierarchy for both images and typography
- **row 8** — Text lines have suitable length: About fifteen words per line seems to be a good consensus.
- **row 9** — Presentation: Is the visual layout well designed?

## 2. Aesthetic

*Interfaces should not contain information that is irrelevant or rarely needed. Every extra unit of information in an interface competes with the relevant units of information and diminishes their relative visibility.*

- **row 4** — The system repeats elements like CTA so completing a task doesn't require more user work than needed.
- **row 5** — The system follows established industry conventions (external consistency).
- **row 6** — The system shows the information in little bits (progressive disclosure)
- **row 7** — Examples are shown (additionally to descriptions)
- **row 8** — The objects on the screen have right affordances; clickable things look clickable
- **row 9** — The system maintain consistency within a single product or a family of products (internal consistency)
- **row 10** — Does the website/app favor maps, diagrams, graphs, flow charts and other visuals over long blocks of text?

## 3.Recover

*Explanation: People make mistakes. The system is prepared for user errors. Error messages are in plan language with no codes and constructively suggesting a solution. The system gives the user a sense of freedom and confidence.*

- **row 4** — It's easy to undo and redo
- **row 5** — A clear way to exit the current interaction, like a Cancel button exists.
- **row 6** — Traditional error message visuals, like bold and red text are used.
- **row 7** — Solutions that can solve the error immediately are offered.
- **row 8** — If an error is detected in a data entry field, does the system place the user in that field or highlight the error?

## 4. Recognition

*Explanation: Human memory is complicated. The user should not have to remember information from one part of the interface to the other. Minimize the user's memory load by making elements, actions and options visible*

- **row 4** — Users aren't required to remember things from one task to another
- **row 5** — Help is offered to user instead of a long tutorial to memorize.
- **row 6** — Is color coding consistent throughout the system?
- **row 7** — Solutions that can solve the error immediately are offered.

## 5. Accessibility

*People have different needs. The system takes this into consideration following basic accessibility principles.*

- **row 4** — The system pays attention to color contrast. Color isn't the only mean it uses to convey a message.
- **row 5** — The system doesn't rely on color as the only means to convey a message. Instead uses a combination of text, color, or graphical objects.
- **row 6** — The system keeps its font size at least 12pt
- **row 7** — The system has a consistent navigation, were all the repeated components occur in the same order on each page.
- **row 8** — Touch targets are at least of approximately 9 mm high by 9 mm wide, independent of the screen device or resolution. And leaves enough inactive space around controls.
- **row 9** — The system has a device-independent design, supporting various screen sizes without loss of information or functionalities.

## 6. Attention

*Users' attention is grabbed and held in the right moments; users aren't distracted when they are paying attention to something important. The system prevents slips and mistakes.*

- **row 4** — The system uses different or novel objects in the interface when it wants the user to pay attention
- **row 5** — Mistakes are prevented by removing memory burdens, supporting undo and warning users. Slips are prevented by providing helpful constraints and good defaults.
- **row 6** — The system doesn't relies on users noticing every change in the interface.
- **row 7** — To grab the attention, the system uses bright colors, large fonts, beeps and tones.
- **row 8** — There aren't unnecessary elements distract users from the information they really need.
- **row 9** — Is white space used to create symmetry and lead the eye in the appropriate direction?

## 7. Status

*People crave information and the system gives the user the information they need in the moment they need it. The design should always keep the user informed about what's going on and appropriate feedback. Is best if the system doesn't need any additional information, however, documentation should be provided to help users understand how to complete tasks.*

- **row 4** — Help documentation is easy to search. And ideally presented in context right at the moment the user requires it.
- **row 5** — It's clear to users what the system's state is - no action with consequences to users should be taken without informing them.
- **row 6** — Feedback is presented to the user as quickly as possible (ideally immediately)
- **row 7** — Trust and credibility are built through open and continuous communication.
- **row 8** — The user is provided with various forms of contact (human agent, email, phone, etc)

## 8. Real world

*The design should speak users' language, words, phrases, and concepts rather than internal jargon. Real world conventions should be followed to make information appear in a natural and logical order. This will depend very much on your specific users. The mental models of those users should be taken into account as well as unconscious processing.*

- **row 4** — When users are required to commit a large action, they are first required to commit a smaller one (progressive disclosure is use in those cases)
- **row 5** — The system matches the users' mental model, or it teaches the users to have the right mental model of the system
- **row 6** — Suitable metaphors are used to helpt users get a conceptual model of the system.
- **row 7** — User research is done to get information about users' mental models and those in consideration.

## 9. Important

*Information is grouped in a way that users' can focus, cluttered interfaces are avoided.*

- **row 4** — The elements of the design are ordered accordingly to similar sibling elements
- **row 5** — Typography is large enough and easy to read
- **row 6** — The system helps guide the user's eye to the most important parts of it
- **row 7** — Do the selected colors correspond to common expectations about color codes?
- **row 8** — Navigation: Is information easy to find?
